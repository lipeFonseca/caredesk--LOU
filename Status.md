## Visão Geral (sem data — descreve o que o projeto é, não muda de lugar)

CareDesk é um sistema interno de acompanhamento pós-operatório de uma clínica. Um agente (ou o admin) cadastra o paciente, vincula um protocolo de contato, e o sistema calcula os marcos de acompanhamento. O scheduler diário gera notificação interna quando um marco vence.

**Escala do produto:** uma clínica, dois papéis fixos — `agent` (cadastro, contato, checklist de documento) e `admin` (tudo isso + protocolos, equipe, identidade visual). Multi-clínica foi avaliado e descartado (ver `2026-07-20`).

**Stack:** React 18 + Vite + Tailwind + Framer Motion (frontend) · Cloudflare Workers + Hono (backend) · Cloudflare D1/SQLite (banco) · Cloudflare R2 (arquivo) · JWT hand-rolled (Web Crypto, sem lib) + cookie `HttpOnly` (sessão).

**Ambientes:**
- Frontend: `https://caredesk-lou.pages.dev`
- Worker: `https://caredesk-worker.faugusto-thecoral.workers.dev`
- Local: frontend `http://localhost:5173` (proxy `/api` → `http://localhost:8787`), worker `http://localhost:8787`
- **D1 local e D1 remoto são bancos separados** — dado, credencial e migration aplicada num não existem automaticamente no outro (ver armadilha em `2026-07-22`).

**Regra de storage:** R2 pra binário grande (logo, background, avatar), D1 pra metadado/relação/permissão. Nunca usar R2 como fonte de dado cadastral/clínico.

  - **Por que não é SMTP:** Cloudflare Workers não abre conexão SMTP (bloqueio antispam da própria Cloudflare), então **senha de app do Gmail não serve** — ela só funciona para SMTP/IMAP. Decisão do usuário depois dessa constatação: **Google Apps Script publicado como Web App** faz a ponte. O rate limit conta o pedido mesmo sem conta existente, senão o próprio limite viraria o detector. Único desvio proposital: `429` real com `Retry-After`, porque sem ele o envio de e-mail vira a arma (flood na caixa da vítima + estouro de cota).
